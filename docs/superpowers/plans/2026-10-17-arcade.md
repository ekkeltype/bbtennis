# Black Belt Tennis Arcade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A second game in this repo, *Black Belt Tennis Arcade*: real-time arcade tennis vs the CPU
with keyboard controls, served at `/bbtennis/arcade/`, reusing the typing game's art, audio,
scoring and UI building blocks without changing how the typing game plays.

**Architecture:**
- **Core:** `src/arcade/core/` is a pure, deterministic 60 Hz stepper (`step(state, inputs)`). Each
  hit is resolved at contact into a closed-form `Flight` built only from a `HitEvent`, and each
  player's hits use that player's own RNG stream. This keeps online play possible later (spec §8).
- **CPU:** a `Controller` that emits the same per-tick `PlayerInput` a human does.
- **Shell:** `src/arcade/{game,render,audio,ui}` is the shell. It reuses shared modules in place;
  where a shared module is tangled with typing logic, the reusable part is first extracted into its
  own file (Tasks 2–3).

**Tech Stack:** TypeScript 7 (strict, `noUncheckedIndexedAccess`, `verbatimModuleSyntax`), Vite 8
(multi-page build), Vitest 5 (Node; jsdom where a test needs a DOM), Canvas 2D, WebAudio.

**Spec:** `docs/superpowers/specs/2026-10-17-arcade-design.md` (the "spec"). Shared conventions come
from the typing game's spec `docs/superpowers/specs/2026-09-26-black-belt-tennis-design.md`.

## Global Constraints

- **The typing game is unchanged in behaviour.**
  - `npm run typecheck`, `npm test` (2,073 passing tests plus everything new) and `npm run build`
    pass at every commit.
  - Existing tests are not edited, except to update an import path after an extraction; any such
    edit is called out in the commit message.
- **Core purity:** `src/arcade/core/` uses no DOM, timers, `Math.random`, `Date` or `performance`.
  - Allowed maths: `+ − × ÷`, `Math.sqrt`, `abs min max floor ceil round sign trunc`.
  - Forbidden: `sin cos tan asin acos atan atan2 sinh cosh tanh exp expm1 log log1p log2 log10 pow
    cbrt hypot` and `**`. The guard test from Task 1 enforces this.
- **Imports:** nothing outside `src/arcade/` imports `src/arcade/`. Runtime imports from `src/arcade/`
  never reach a typing-only module (guard test, Task 1).
- **Units:**
  - Core state time is the integer `tick` (60 per second, `DT = 1/60` s).
  - Flight-relative times and all physics constants are in seconds and metres.
  - Render and UI animation use milliseconds.
- **Coordinates:** the typing game's, spec §4.
  - Player 0 is at end 0 (y < 0). `endSign(0) = +1`, `endSign(1) = −1`.
  - A player's "right" is world `+x × endSign(player)`; "toward the net" is `+y × endSign(player)`.
  - The near player's screen-right is +x (viewer 0).
- **State** is plain JSON-safe data: finite numbers, strings, booleans, null, arrays, plain objects.
- **Storage keys** are prefixed `bbtennis-arcade:v1:`.
- **Commits** use the repo's `type(scope): summary` style, e.g. `feat(arcade): flight model`, and end
  with:
  ```
  Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
  ```
- **Branch:** `arcade`. Never commit to `main` until Task 15.

## Review Focus

1. **A key held while the window loses focus or the match pauses.** It must not stay "held":
   movement stops and no stuck charge remains. Test in Task 10.
2. **A tap shorter than one tick** (keydown and keyup between two ticks). It still commits or tosses.
   Test in Task 10.
3. **Two shot keys pressed on the same tick.** Priority is fixed: topspin > slice > lob, the same on
   every machine. Test in Task 7.
4. **The serve clock running out while the ball is in the air.** It is a time-violation fault, not a
   hit. Test in Task 7.
5. **A frame stall** (tab throttled, debugger). The session runs at most 15 catch-up ticks per frame
   and drops the rest, so players never teleport. Test in Task 10.

```ts
import type { CallKind, DeuceRule, FormatId, PaceId, PlayerId, PlayerInfo, PointReason, RngState, ScoreState, Side, Surface, Vec2, Vec3 } from '../../core/types';

export type { CallKind, PlayerId, PlayerInfo, PointReason, Side, Vec2, Vec3 };

/** A rally stroke chosen with a shot key (spec §4.1). */
export type ShotKey = 'topspin' | 'slice' | 'lob';
/** What actually flies: a rally stroke, the overhead smash or one of the three serves (spec §4.6, §4.8). */
export type ShotType = 'topspin' | 'slice' | 'lob' | 'smash' | 'serveFlat' | 'serveSlice' | 'serveKick';
/** Timing grade of a hit (spec §4.3, §4.8). */
export type Grade = 'perfect' | 'clean' | 'rushed';

/**
 * One player's controls on one tick (spec §4.1), court-relative for that player: mx +1 = the
 * player's right, my +1 = toward the net. Shot keys are held states; the sim detects presses.
 */
export interface PlayerInput { mx: -1 | 0 | 1; my: -1 | 0 | 1; topspin: boolean; slice: boolean; lob: boolean }

/** No keys held. */
export const NO_INPUT: Readonly<PlayerInput> = Object.freeze({ mx: 0, my: 0, topspin: false, slice: false, lob: false });

/** Produces a player's input each tick: the keyboard for a human, a planner for the CPU. */
export interface Controller { input(s: Readonly<ArcadeState>): PlayerInput }

/** Options a match is played with (spec §4.6 pace, §4.9 scoring). Surface is cosmetic. */
export interface ArcadeConfig { format: FormatId; deuceRule: DeuceRule; surface: Surface; pace: PaceId }

/** Everything that decides a hit's flight (spec §8: enough for both machines to build the same flight). */
export interface HitEvent {
  tick: number;
  player: PlayerId;
  type: ShotType;
  grade: Grade;
  stretch: boolean;
  volley: boolean;
  /** Power factor after grade and stretch (1 = base speed). */
  power: number;
  /** Ball position at contact. */
  contact: Vec3;
  /** Landing target after aim and scatter (ground point on the receiver's half). */
  target: Vec2;
  /** Seconds from contact to the first bounce, after scatter and the apex clamp. */
  T: number;
}

/** One parabolic piece of a flight, valid from `t0` (s after the hit) until the next segment's t0. */
export interface FlightSegment { t0: number; p0: Vec3; v0: Vec3; a: Vec3 }

/** A bounce: seconds after the hit and the ground point. */
export interface FlightBounce { t: number; at: Vec2 }

/** The closed-form path of a hit ball (spec §4.6). */
export interface Flight {
  hit: HitEvent;
  segments: FlightSegment[];
  /** In time order. Empty for a net ball. bounces[0] is the landing that decides in/out. */
  bounces: FlightBounce[];
  /** Seconds after the hit when the ball reaches the net plane y = 0, or null. */
  netT: number | null;
  /** True when the net stops the ball. */
  net: boolean;
  /** Seconds after the hit when the ball is dead for the rules: second bounce, left the surround, or (net) on the ground. */
  tEnd: number;
  /** Seconds after the hit when drawing stops (rolls on past tEnd). */
  tGone: number;
}

/** Swing drawn for a player's latest contact. */
export type Stroke = 'forehand' | 'backhand' | 'smash' | 'serve';

export interface PlayerState {
  pos: Vec2;
  vel: Vec2;
  /** Committed shot and the tick it was committed at (spec §4.3); null when not committed. */
  commit: { shot: ShotKey; tick: number } | null;
  /** Shot keys held on the previous tick (press = false → true). */
  held: { topspin: boolean; slice: boolean; lob: boolean };
  /** The player's latest contact, for animation. */
  lastSwing: { tick: number; stroke: Stroke; stretch: boolean } | null;
}

/** Match phase; ticks are absolute. */
export type Phase =
  | { kind: 'intro'; until: number }
  | { kind: 'setup'; since: number }
  | { kind: 'toss'; at: number }
  | { kind: 'rally' }
  | { kind: 'dead'; until: number; next: 'setup' | 'over' }
  | { kind: 'over'; since: number };

/** Per-player match statistics (spec §6.3 Results). */
export interface ArcadeStats {
  pointsWon: number;
  aces: number;
  doubleFaults: number;
  winners: number;
  errors: number;
  hits: number;
  perfectHits: number;
  fastestServeKmh: number;
}

/** Complete match state (JSON-safe). */
export interface ArcadeState {
  v: 1;
  config: ArcadeConfig;
  players: [PlayerInfo, PlayerInfo];
  tick: number;
  phase: Phase;
  score: ScoreState;
  p: [PlayerState, PlayerState];
  /** The live flight (rally, and the dead phase while it is drawn); null otherwise. */
  flight: Flight | null;
  /** The toss in the air (phase 'toss'). */
  toss: { tick: number; player: PlayerId } | null;
  point: {
    serveNo: 1 | 2;
    /** In-play hits this point, the serve included. */
    hits: number;
    /** True while the serve has not bounced yet (the receiver cannot reach it, spec §4.4). */
    serveUnbounced: boolean;
    /** The latest call, for banners: kind, who it is against, at which tick. */
    call: { call: CallKind; player: PlayerId; tick: number } | null;
  };
  /** Tick at which the current serve's clock started (setup start), or null outside a serve. */
  serveClockFrom: number | null;
  stats: [ArcadeStats, ArcadeStats];
  longestRally: number;
  pointNo: number;
  status: 'playing' | 'over';
  winner: PlayerId | null;
  /** Hit-scatter streams per player (spec §4.7) and the match stream (coin toss). */
  rng: { hits: [RngState, RngState]; match: RngState };
}

/** Events, stamped with the tick they happened on. */
export type ArcadeEvent = { tick: number } & (
  | { type: 'coinToss'; winner: PlayerId }
  | { type: 'setup'; server: PlayerId; serveNo: 1 | 2; side: Side }
  | { type: 'toss'; player: PlayerId }
  | { type: 'tossDropped'; player: PlayerId }
  | { type: 'commit'; player: PlayerId; shot: ShotKey }
  | { type: 'hit'; hit: HitEvent; kmh: number }
  | { type: 'bounce'; at: Vec2; inCourt: boolean }
  | { type: 'netHit'; at: Vec3 }
  | { type: 'call'; call: CallKind; player: PlayerId }
  | { type: 'point'; winner: PlayerId; reason: PointReason }
  | { type: 'game'; winner: PlayerId }
  | { type: 'set'; winner: PlayerId }
  | { type: 'match'; winner: PlayerId }
  | { type: 'situation'; text: string }
);
```

export function buildFlight(hit: HitEvent): Flight;
/** Ball position `t` s after the hit; t is clamped to [0, tGone]. */
export function flightPos(f: Flight, t: number): Vec3;
/** Ball velocity `t` s after the hit (the segment's v0 + a·(t − t0)). */
export function flightVel(f: Flight, t: number): Vec3;
/** Initial vertical speed and apex of an arc from height z0 that lands (z = 0) after T s with gravity g·k. */
export function arcApex(z0: number, k: number, T: number): number;

export function clampTForApex(z0: number, k: number, T: number): number;

/** True when a ground point is in `receiver`'s service box for a serve from `side`, lines in, the ball radius added. */
export function inBoxFor(p: Vec2, receiver: PlayerId, side: Side): boolean;

**The model.**
- **Segment 0.** `a = (ax, 0, −g·k)`, where `ax = serveSliceCurve × sign(target.x)` (sign 0 → +1) for
  `serveSlice` and 0 otherwise. `v0 = ((L.x − p0.x)/T − ½·ax·T, (L.y − p0.y)/T, −p0.z/T + ½·g·k·T)`,
  with `p0 = hit.contact` and `L = hit.target`.
- **Net check.** If p0.y and L.y have opposite signs, `netT = −p0.y / v0.y`. At netT the ball's z is
  compared with `netHeightAt(x) + ballRadius`. Below it means a **net ball**:
  - segment 1 starts at the net point with `v = (keepX·vx, −backY·vy, 0)` and `a = (0, 0, −g)`;
  - `tEnd = tGone = netT + sqrt(2·z/g)`;
  - `bounces = []`, `net = true`.
- **Otherwise:**
  - The first bounce is at `T`, at `L`.
  - Segment 1 starts at `(L, 0)` with `v = (keep·vx(T), keep·vy(T), −rest·vz(T))` and
    `a = (0, 0, −g)`. Its second bounce comes after `2·vz/g`.
  - `tEnd = min(second bounce, the time the ball leaves the surround |x| > 9 or |y| > 18)`.
  - Then up to `laterBounce.max` more segments use `laterBounce.keep/rest`, until it leaves the
    surround. `tGone` is the end of the last segment, capped at `tEnd + 3 s`.
- **Bounce times** come from the segment's own quadratic, solved with `Math.sqrt` only.

**Behaviour** (state kept inside the instance, deterministic):
- **Serving (setup phase, CPU is the server):**
  - Waits `U(0.6, 1.2)` s from the set-up start, then taps the chosen key for one tick (the toss).
  - Serve choice: first serve flat with probability = aggression, else slice; second serve kick.
  - Aim: wide/T/body. Corner (wide or T, 50/50) with probability `0.25 + 0.6·aggression`, else body.
  - It holds the aim direction from 2 ticks before its hit tick.
  - Hit tick = toss + apex + perfectWindow/2 + N(0, pressSigma), in ticks, clamped to before the
    drop. On that tick it taps the serve key.
  - Taps are one tick down, then up.
- **Receiving / rallying (the ball flies toward the CPU):**
  - **Reaction.** For `reaction` s after the opponent's hit tick it keeps its previous movement plan.
  - **Prediction.**
    - Sample the flight at each future tick until `tEnd`. Pick the first tick at which the ball is
      at height 0.5–1.4 m after the bounce (volley allowed when the CPU is within 4 m of the net:
      any in-zone height).
    - Contact spot = ball point + 0.7 m to the CPU's forehand or backhand side, whichever is closer
      to its current x.
    - Add the read error (a per-shot offset ~ N(0, readError) in x and y), scaled linearly to 0
      over the last 0.5 s before the predicted contact.
  - **Steering.** Direction = sign of the delta in the CPU's court frame, with a deadband of 0.15 m.
    A speed factor below 1 is applied with an accumulator: `acc += speed`, and the direction is held
    only when `acc ≥ 1` (then `acc −= 1`).
  - **Commit.** At predicted contact − (chargeTime + perfectWindow/2 + N(0, pressSigma)), tap the
    shot key.
  - **Shot choice:**
    - stretched (predicted lateral > 1.0) → slice;
    - else if the opponent is within 4 m of the net → lob with probability `0.3 + 0.5·aggression`;
    - else topspin.
  - **Aim:**
    - corner away from the opponent with probability `0.25 + 0.6·aggression`;
    - depth: deep (my = +1) with probability 0.5, else neutral;
    - a CPU within 4 m of the net aims short with probability 0.3;
    - hold the aim for the last 2 ticks before the predicted contact.
  - **Recovery after its own hit:** steer to `(0.6·sign(own target x), behind-centre y = baseline +
    0.8 m)` in world terms on its half. After a contact more than 4 m inside the baseline with
    aggression > 0.5, it steers to the net position, 2.5 m from the net.
- **Other phases:** `NO_INPUT`. As the receiver in setup or toss: `NO_INPUT`.
